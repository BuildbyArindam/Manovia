# Day 47 verification — clinician-share bridge (consented, time-limited, standards-based)

Run on 2026-10-20 in the Arena sandbox, branch `arena/52032e59-manovia` (the
session branch Arena pins; the requested
`day-47-clinician-share-bridge-consented` could not be created or pushed from
here, same as Days 38–46). No main push.

Every number below comes from a real run on this machine. Where something could
not run here, it says so and points at what covers it instead.

Values that look like credentials — a share token, the URL secret, derived-key
material, ciphertext prefixes — are **abbreviated to their first 8 characters**
throughout, so nothing in this file can be mistaken for a live secret by a reader
or by a scanner. They came from a throwaway test database and were 22 characters
(token), 43 (secret) and 32 bytes (key) in full. The assertions behind each
transcript line use the complete values; only the prose shortens them.

## What this sandbox cannot do

| Not available | Consequence | Covered instead by |
| --- | --- | --- |
| A JVM (`java` is not installed) and egress to GitHub release downloads | The **official HL7 validator** cannot execute here | The `fhir-validation` CI job runs it on every push and PR (jar sha256-pinned, temurin 17, `-version 4.0.1 -tx n/a`); locally `make fhir-validate` runs `backend/scripts/fhir_offline_check.py`, whose 25 tests include 16 mutations it must catch |
| A browser | The viewer page is never rendered by a real engine | 14 jsdom tests drive `ShareViewer` through the real WebCrypto path against a committed ciphertext vector; 2 `App.test.tsx` tests pin the routing rules |
| A downloadable Playwright browser | No end-to-end click-through of create → open | Listed in "What you should test by hand" below |
| `tx.fhir.org` | No live terminology lookup | LOINC codes are pinned with their loinc.org source URLs in `backend/app/content/sharing/loinc.json` (read 2026-10-19) and enforced by the offline checker; the CI job has a non-blocking run against the real server |

And the search that makes "ciphertext only" a statement rather than a hope —
every column of the row serialised, then looked through for the plaintext:

```
searched every column of the row for five things (full values, not prefixes):
  the note      'I have been sleeping badly and I wou…'  -> found: False
  a question    'Is this normal?'                        -> found: False
  the token     (22 characters)                          -> found: False
  the secret    (43 characters)                          -> found: False
  the passcode  (6 digits)                               -> found: False
```

Each ciphertext is exactly its plaintext plus the 16-byte GCM tag, which is what
AES-256-GCM produces and is the arithmetic proof that no plaintext is hiding in
the row.

### LOINC codes, and where each was read

| Code | Display (as loinc.org states it) | Source URL | Scale / method / unit / status |
| --- | --- | --- | --- |
| `44261-6` | Patient Health Questionnaire 9 item (PHQ-9) total score [Reported] | <https://loinc.org/44261-6> | Qn / Reported.PHQ / `{score}` / active |
| `70274-6` | Generalized anxiety disorder 7 item (GAD-7) total score [Reported.PHQ] | <https://loinc.org/70274-6> | Qn / Reported.PHQ / `{score}` / active |

Read off loinc.org on **2026-10-19** and pinned in
`backend/app/content/sharing/loinc.json` with their fully-specified names
(`Patient health questionnaire 9 item total score:Score:Pt:^Patient:Qn:Reported.PHQ`
and `Generalized anxiety disorder 7 item total score:Score:Pt:^Patient:Qn:Reported.PHQ`).
The questionnaire **panel** codes `44249-1` (<https://loinc.org/44249-1>) and
`69737-5` (<https://loinc.org/69737-5/panel>) are recorded beside the totals and
never used — a panel code on a total-score Observation is the mistake the file
exists to prevent, and the loader rejects one presented as a total.

Both units are `{score}`, LOINC's own example UCUM unit for these terms, emitted
with `system: http://unitsofmeasure.org`. Observation categories use `survey`
from `http://terminology.hl7.org/CodeSystem/observation-category`; provenance
agents use `author` and `assembler` from
`http://terminology.hl7.org/CodeSystem/provenance-participant-type`. Everything
Manovia-specific is in `https://manovia.app/fhir/CodeSystem/…`:

```
local mood-summary|mean-valence   'Mean mood rating'             value=3.0
local mood-summary|mean-energy    'Mean energy rating'           value=3.5
local mood-summary|check-in-count 'Number of mood check-ins'     value=6
local mood-summary|direction      'Direction of mood ratings'
LOINC  70274-6 value=9  unit='{score}' category=['survey'] status=final
LOINC  44261-6 value=12 unit='{score}' category=['survey'] status=final
```

## What you should test by hand

1. **The official FHIR validator.** Push the branch (or open the PR) and read the
   `fhir-validation` job: the sha256 check, the freshness check, the offline
   check, then the validator's own output and exit code. This is the one item in
   the table above that no local run could complete.
2. **Create a share in a real browser.** Sign in, Settings → sharing on,
   `/shares`: tick items, watch the live preview change, confirm the consent
   lines, create. Check the link panel shows the key once and says it cannot be
   recovered.
3. **Open it in a private window** (no account): the banner, the passcode prompt,
   then the document. Download the PDF and open it — check the banner on page 1
   and the footer on every page. Download the FHIR bundle and open it in a FHIR
   viewer of your choice.
4. **Lose the key on purpose.** Open `/s/<token>` without `#k=…`: the page should
   explain the key is missing and not offer a way in.
5. **Break the ciphertext.** Edit one character of a document's base64 in the
   response (devtools) and confirm the viewer shows one refusal message, not a
   partially rendered document.
6. **Wrong passcode five times.** Confirm the tries-left message counts down and
